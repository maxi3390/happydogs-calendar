# Design — upgrade-docusaurus

## What was blocking Node 24 in the docs container

Three issues stacked, each surfaced by npm 11's stricter behaviour:

1. **Lockfile drift on optional deps.** `docs/package-lock.json` was generated by an older npm (probably npm 10 on Node 20) that didn't record `fsevents@2.3.3`. npm 11 detects the missing optional and refuses `npm ci` — `Missing: fsevents@2.3.3 from lock file`.

2. **Docusaurus version-coherence check.** With `@docusaurus/theme-mermaid: "^3.9.2"` and `@docusaurus/core: "3.9.2"` exact, a fresh resolve picked `theme-mermaid@3.10.0` (latest minor, satisfies `^`). Docusaurus's own runtime check then refused the build:
   ```
   Invalid name=docusaurus-theme-mermaid version number=3.10.0.
   All official @docusaurus/* packages should have the exact same version
   as @docusaurus/core (number=3.9.2).
   ```

3. **Webpack ProgressPlugin schema.** After pinning every `@docusaurus/*` to the same `3.10.0` and regenerating, the build hit:
   ```
   ValidationError: Invalid options object. Progress Plugin has been initialized
   using an options object that does not match the API schema.
     - additionalProperty: 'name'
     - additionalProperty: 'color'
     - additionalProperty: 'reporters'
   ```
   `@docusaurus/bundler@3.10.0` calls `new webpack.ProgressPlugin({ name, color, reporters, reporter })`. webpack 5.x's `ProgressPlugin` schema started rejecting these keys somewhere after the version Docusaurus tested against. The Docusaurus declared dependency is `webpack: ^5.95.0`; the resolved version under a fresh npm 11 install was newer.

## The fix

Three small changes:

```json
// docs/package.json

"dependencies": {
  "@docusaurus/core": "3.10.0",
  "@docusaurus/preset-classic": "3.10.0",
  "@docusaurus/theme-mermaid": "3.10.0",      // was "^3.9.2"
  "react": "^18.0.0",
  "react-dom": "^18.0.0"
},
"devDependencies": {
  "@docusaurus/module-type-aliases": "3.10.0",
  "@docusaurus/tsconfig": "3.10.0",
  "@docusaurus/types": "3.10.0",
  "typescript": "~5.2.1"
},
"overrides": {
  "webpack": "5.95.0"
}
```

And in the Dockerfile:

```diff
-FROM node:20
+FROM node:24-alpine
```

`npm ci` keeps working because `docs/package-lock.json` is regenerated under Node 24 as part of this change.

### Why pin all `@docusaurus/*` to exact `3.10.0`?

Docusaurus enforces version coherence across its own ecosystem at runtime. Using `^3.x.y` for any of them lets the resolver drift one package into a different minor than core, which triggers the build-time refusal we saw. Pinning to the same exact version sidesteps the drift entirely.

The cost is that future patch updates (3.10.1, 3.11.x) require touching `docs/package.json` instead of just running `npm update`. For a docs-only project with infrequent dep churn, that's the right tradeoff.

### Why pin webpack via `overrides` instead of bumping Docusaurus?

The `overrides` block is intentionally an interim. The proper fix is for Docusaurus to update its `ProgressPlugin` call to drop the keys current webpack rejects, which is a Docusaurus-internal change we can't make here. Once a future Docusaurus release lands that fix, we can drop the override.

Until then, `overrides.webpack: "5.95.0"` pins every transitive webpack copy in the graph to the version Docusaurus 3.10.0 tests against. npm 11 honours `overrides` across all transitives, so `webpack-bundle-analyzer`, `webpack-dev-server`, etc. all resolve to a consistent 5.95.0.

## Verification

```bash
# Inside node:24-alpine, against the regenerated lockfile
npm ci                      # succeeds (no missing optionals)
npm run build               # succeeds (no ProgressPlugin error)

# Through docker compose
docker compose --profile docs build docs   # builds clean
docker compose --profile docs up -d docs   # boots, in-container build runs
```

## Out of scope

- A different docs framework. Docusaurus 3.10.0 covers the project's needs; the upgrade matrix is small.
- Pinning `node` engine in `docs/package.json`'s `engines` field. The compose / Dockerfile is the source of truth; package.json's `engines` stays at `">=18.0"` so local installs on older Node still work for ad-hoc edits.
- Dropping the `webpack` override. Reassess when Docusaurus releases a version with a fixed ProgressPlugin call.
